# Workflow and output contract

This document describes the stages, actual outputs, and result interpretation of the unified commands. The current command's `--help` defines its parameters; actual JSON output defines its fields. Do not use examples as execution evidence.

## Commands and input

Use `python scripts/literature.py` from the source checkout, or `literature-workflow` after installing the Python package.

| Command | Input and key options | Stages |
|---|---|---|
| `doctor` | `--mode search\|download\|all` | Local dependency and configuration diagnostics; no network requests |
| `search QUERY` | `--sources`, `--rows`, date/author/document-type filters | Search by source, normalize, and deduplicate |
| `verify` | Repeatable `--doi`, `--id`, `--citation`, or `--input`; optional `--expected-title` and `--expected-year` | Parse input, look up identifiers, and compare expected fields |
| `download` | Repeatable `--doi`, `--url`, `--citation`, or `--input`; optional `--no-browser`, `--profile-root`, `--headless`, and `--wait` | Resolve, verify as needed, acquire from official sources, and check PDFs |
| `search-download QUERY` | Search and download options | Run search, verification, and official downloads in sequence |
| `export` | `--input`, `--format ris\|bibtex` | Export eligible citations from records |

All workflow commands support `--output` and `--language zh|en` (the CLI defaults to English). We recommend explicitly specifying a new or empty, separate output directory for each run; nonempty directories are rejected and existing results are not overwritten. When `--output` is omitted, the command creates a separate directory for the run under `outputs/`.

`search` and `search-download` support `--date-from YYYY-MM-DD`, `--date-to YYYY-MM-DD`, `--author TEXT`, and repeatable `--document-type TYPE` (for example, `journal-article`). Requested filters are recorded in `run.json` under `requested_filters`. Source support and execution can differ; explain them using source records and actual scope in the results. Passing a parameter does not establish that all sources applied the same filtering rules.

Provide DOIs, identifiers, titles, ordinary citations, or official links directly. File input supports JSON, CSV, and text. RIS/BibTeX input currently extracts DOI-bearing records only and does not import the full format syntax; the CLI rejects RIS/BibTeX files without DOIs, so they must not be described as fully imported. Supply ordinary titles or citations as text or through `--citation` for conservative identity resolution. Retain unresolved identities as pending items without fabricating records; one ambiguous record should not prevent resolvable items from continuing.

## Actual outputs

| File or directory | Contents |
|---|---|
| `run.json` | Current task, executed stages, scope, and status |
| `records.json` | Literature records, source information, verification, and conflicts |
| `report.md` | Results, coverage gaps, and pending items for the user |
| `download_manifest.json` | Download targets, acquisition results, file validation, and source associations |
| `papers/` | Files that passed provenance and PDF checks |
| `references.ris` or `references.bib` | Citation exchange files generated by `export` |

The first three are common workflow outputs; downloads also produce a manifest and papers directory. Link only files that were actually generated. Responses or files that fail checks do not enter `papers/`. Failures and pending items remain in the JSON and report.

## Sources and search scope

Six paper sources are implemented: `crossref`, `pubmed`, `arxiv`, `openalex`, `europe_pmc`, and `semantic_scholar`. The default query uses `crossref,europe_pmc`. An existing source adapter, existing configuration, or coverage in upstream documentation does not establish a successful query in the current run.

Results record actual source operations in `sources_queried`, `sources_succeeded`, `sources_failed`, `sources_not_queried`, and `errors`. `coverage` retains source-reported totals, acquired counts, and truncation reasons when supplied by the source. Valid zero results differ from request failures, and error responses within HTTP 200 do not count as success. `--rows` currently accepts 1–50 and bounds the number acquired per source, not the final deduplicated paper count; a bounded search cannot establish complete coverage.

The same normalized request follows one search execution path, without duplicate queries due to overlapping upstream sources. Independent verification and justified retries can be recorded as new operations.

## Paper identity and verification

Preserve the mapping between original inputs and resolved records, using strong identifiers such as DOI, PMID, and arXiv IDs as identity evidence. Title similarity provides matching clues only. Conflicting identifiers or bibliographic fields must not be silently overwritten by the latest returned value; preserve version differences among preprints, revisions, and published versions.

Verification explains lookup evidence, compared fields, matches or conflicts, and fields unavailable from the source. Finding a record by DOI alone does not establish that the original citation's title, authors, or year are correct. When the user supplies an expected title or year, report the actual comparison for that field; fields not compared remain unchecked.

| `metadata_status` | Meaning |
|---|---|
| `not_checked` | Candidate only; no independent lookup yet |
| `verified` | Fields within the declared verification scope match, with no unresolved identity conflicts |
| `partial` | Some expected fields or identifiers are missing or cannot be verified |
| `mismatch` | Expected fields, identifiers, or versions conflict |
| `unresolved` | No reliable matching record has been obtained |

Interpret statuses together with `verification_scope`, `field_checks`, `verified_fields`, `unchecked_fields`, `unchecked_identifiers`, and `conflicts`. `verified` covers only the declared verification scope; it does not mean that the entire paper was read or every bibliographic field was checked.

The following judgments are independent:

- Candidate discovery and identity resolution: obtaining a potentially relevant literature record.
- Metadata verification: declared fields match the source.
- PDF acceptance: file provenance is eligible, pages are readable, and identity matches the target paper.
- Claim support: reading a paper to assess whether it supports a particular claim; this CLI does not do this automatically.
- Manual citation selection: the user decides which papers to cite in a manuscript.

## Official PDF acquisition and acceptance

Use a DOI or official publisher article page as a stable entry point. A supplied PDF URL remains a candidate whose host provenance and file identity must be checked. Prefer HTTP, selecting browser acquisition according to the environment and request. Each browser run creates a new, separate UUID profile; `--profile-root` specifies only its parent directory and does not reuse existing user logins or cookies. When authorized access is required, the user can log in manually in the current visible browser; persistent reuse is not promised. Do not deliver files from unknown or ineligible sources as official files.

File acceptance requires PDF format, readable pages, and identity evidence matching the target paper, with provenance and validation information retained. File existence, a download event, HTTP 200, or the CLI exit status alone cannot replace acceptance checks.

Retain pending status and reasons when access rights are missing, access verification is incomplete, the response is not a PDF, or identity is unknown or conflicting. Do not keep repeating aggressive retries, switch to third-party copies, or bypass access controls; continue records in the batch that can be clearly processed.

## Citation export and privacy

By default, export only records with `metadata_status=verified` and `entity_type=publication`; unmatched strong identifiers do not enter formal citation fields. Do not silently export unchecked, conflicting, unresolved, or trial-registration records as verified papers. Report actual export counts, omission reasons, verification scope, and remaining gaps. Export does not constitute final citation selection or automatically modify a reference library or manuscript.

Result files, reports, and logs must not contain API keys, authorization headers, cookies, browser login state, or signed URL parameters. Browser profiles, binaries, virtual environments, and paper PDFs are local runtime materials, not part of the public source package.
